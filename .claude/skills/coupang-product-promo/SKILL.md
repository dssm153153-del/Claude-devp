# coupang-product-promo

검증된 원칙만 적는다. 사례·사고 기록은 각 프로젝트 폴더(`work/…/PLAN.md`, `storyboard.md`)에 남기고 여기에는 넣지 않는다. 새 교훈이 생기면 해당 원칙 문장을 고쳐 쓴다(뒤에 덧붙이지 않는다).

## 1. 계정·페르소나
- `@pathtorich7`, 닉네임 "꿀팁 줍는 형". 쿠팡 파트너스(판매자 아님). 주 고객 20~40대 여성.
- **화자 = 20대 남성 큐레이터, "주워 와서 보여 주는 사람".** 물건을 사서 써 본 사람도, 반려동물 주인도 아니다. 영상 속 장면을 옆에서 구경하며 감탄·태클하는 친구 같은 말투.
  - 쓰는 말: "뭐야 ~;;", "~ 강림함ㅋㅋㅋ", "시선 강탈", "반칙 아님?"(감탄형), "~ 안 쳐다볼 수가 있나", "이건 그냥 ~임", "~ 미루게 생겼네", ㄷㄷ·ㅋㅋ·😂🥹 소량.
  - 안 쓰는 말: "달아줬더니/사봤는데/써보니/우리 집 ○○/보호자가/책상에 뒀는데/커피 식는 줄도 몰랐음"(지어낸 사용 경험), 여성 1인칭, 정보 나열, "추천템·구매·할인".
  - 이유: 영상은 AI 또는 판매자 영상이다. 경험담은 지어낸 후기가 되고 소개의 "팩트체크"와 충돌, 링크 글에서는 광고 신뢰를 깎는다(GPT 초안은 대부분 경험담으로 나오므로 구경꾼 시점으로 고쳐 쓴다).
- 팔로워는 웃기러·구경하러 온다. **보는 순간 반응이 오는 것만** 올린다: 웃김·감탄·아찔·귀여움(동물)·눈으로 보이는 반전.
- 하지 않는 것: 퀴즈, 정보·단축키·생활정보 나열, 모음집·슬라이드, "생각하게 하는 글".
- 성과 기록: `work/account-analysis/README.md`.

## 2. 소재 고르기 (셋 다 통과해야 함)
1. 첫 1초에 멈추게 한다(색·움직임·반전).
2. 설명 없이 이해된다.
3. 한마디 하고 싶어진다("나라면 못 함", "우리 집도 이럼", "이거 반칙 아님?").
- 한 글 = 한 장면(사진 1장 또는 10초 안쪽 영상 1개).
- 2단계 홍보로 이어질 상품이 자연스러우면 가산점(고양이 문 열기 → 문고리 잠금장치).
- 실패한 소재는 골라서 재업로드하지 않고 버린다.

## 3. 제작 방식 결정
| 상황 | 방식 |
|---|---|
| 원본 영상이 있고 동작이 핵심(손 조작, 기계 움직임, 천·매듭) | **동영상 수정(MiniMax H3)**: 원본 움직임 그대로, 외형·화질·날씨만 교체 |
| 원본 없이 아이디어만 있음 | **GPT 이미지(Start/Mid/End) + Kling O1 Start/End** |
| 사용자가 직접 찍을 수 있음 | **직촬 우선**(문구에 "직접 해봄" 가능, 신뢰↑) |
| 남의 영상 저화질 화면녹화 | 보정만으로 그대로 쓰지 않는다(선명해지지 않고 저작권 그대로) → 동영상 수정으로 재렌더 |
- 쓰지 않는 것: 소품 조작 영상에 Kling Motion Control(몸만 복사, 소품 변화 안 됨), Start만 받는 Kling 2.5(끝 이미지 없이 여러 단계 동작을 지어냄), Runway Aleph(비쌈).

## 4. 도구 설정
### 동영상 수정 (Freepik/magnific → 동영상 → 툴 → 동영상 수정)
- 소스 영상 업로드 → 모델 **MiniMax H3** → "미디어 추가"로 참조 이미지(@img1…) → 프롬프트에서 `@img1`로 지칭 → **해상도는 가장 낮은 옵션(768)**. 2K는 2400크레딧이다. 해상도를 프롬프트와 함께 반드시 지정한다.
- 출력 길이·비율은 **소스를 따른다**(가로 11.4초 소스 → 2560x1440 11.54초, 움직임 전 구간 일치). 소스에 없는 시간은 지어내므로, 원하는 구간만 정확히 잘라 넣는다. 녹화 팝업·워터마크 프레임은 넣기 전에 제거.
- **소스 영상의 손·얼굴이 흐리거나 기괴하면(저화질·모션블러) 동영상 수정에 쓰지 않는다** — 결과가 소스를 따라간다. 소스를 보내기 전에 손 부분을 0.125초 간격으로 확대 확인하고, 문제가 있으면 Kling O1 Start/End(깨끗한 정답 이미지 2장)로 만든다.
- 참조 이미지: 원본 첫 프레임을 GPT로 원하는 외형으로 다시 그린 정답 이미지(구도·구조 그대로). 순서: 직전 클립 마지막 프레임 → 첫 프레임 정답 이미지 → 상품 사진.
- **정답 이미지의 표정·손에 든 물건이 결과를 지배한다**(소스보다 우선). 정답 이미지를 원본 해당 프레임과 나란히 놓고 표정·소품을 확대 비교한 뒤 넘긴다.
- **중국 개발사 모델(MiniMax H3·Kling·Seedance 등)은 프롬프트를 중국어로 쓴다(기본값).** 검수 통과가 쉽고 동작 재현도 정확했다(next8: MiniMax 영어 2회 검수 거절 → 중국어 1회 통과, 뽀뽀·쓰다듬기·안기 타이밍·얼굴 원본대로). 사용자에게는 같은 내용의 한국어 설명을 함께 준다. 그래도 거절되면 다른 모델 → 3D 애니 순. (GPT 이미지·Gemini 등 미국 모델은 영어)
- 짧은 소스(2초)도 출력은 약 5.17초로 늘어남 → 합본 때 배속. 소스 최소 2초.
- 프롬프트: ① 원본 동작을 프레임 단위로 유지, 새 동작·부품 추가 금지 ② @img1에 맞춰 바꿀 것만 ③ 같은 구도.

### GPT 이미지
- 사실적인 폰 사진 톤("realistic smartphone photo, ordinary daylight"). 영화 조명·빛 먼지·보케 금지.
- 끝·중간 이미지는 **시작 이미지를 첨부해 편집**: "Keep the exact same … do not redraw the background. Change only this: …".
- **동작은 물리로 설계한다.** 밀기·당기기·잡기 같은 동작은 ①힘의 출발점(어깨·팔꿈치·손목 중 어디서) ②힘의 방향(좌→우 수평 등) ③접촉점(손바닥이 계속 닿아 있는지) ④관절 각도 변화(팔꿈치 90°→120° 등, 범위를 숫자로) ⑤받는 쪽 반응(이동 거리·회전·머리카락이 늦게 따라옴) ⑥반작용(상체가 따라 기울기)을 원본 프레임에서 확인해 프롬프트에 적는다. "쭉 뻗는다" 같은 과장 단어 금지. **힘의 크기도 현실적으로**: 아이가 어른 체중(머리)을 크게 밀 수는 없다 → 이동량을 작게, 생성 후 무리한 뒷부분은 잘라 쓴다.
- **물건 상태가 바뀌는 동작**(손잡이 눌림, 문 열림, 매듭, 뚜껑)은 처음부터 그 상태를 과장해 보여 주는 **Mid 이미지**를 만들어 클립을 나눈다. Start/End에서 물건 상태가 같으면 모델은 그 변화를 건너뛴다.
- 원본 포즈를 바꾸는 이미지: 1) 원본 프레임 그대로 다시 그리기 → 2) 인물·의상·상품만 교체 → 3) 필요하면 배경. 보이지 않는 부위(소매·손목·팔찌)를 지시하지 않는다(팔이 하나 더 생김).
- 불합격이면 부분 수정 반복 금지 → 모든 요구사항을 담아 처음부터 다시(-v2).

### Kling O1 (Start/End)
- 시작·끝 이미지 모두 넣는다. 5초. 다음 클립 시작 = 이전 클립의 끝 튐 직전 프레임(`K-Last.png`, 내가 뽑아 먼저 보냄).
- 프롬프트 4부, **한 블록**(입력창 하나, 네거티브 칸 없음): 한 줄 요약 / 동작 시간순 + "— matching the End Image composition." / "Static locked-off camera, no movement. Realistic smartphone video." / 유지 문단 + "always exactly four legs…, No new objects, no slow motion, no text."

### 오디오
- 효과음: 파일명 + 프롬프트 + **길이 3초**(최소값)로 요청. `promo.py peak`로 정점을 찾아 0.15~0.3초만 잘라 동작 순간에 정점을 맞춘다.
- 실제 장면(동물·생활)은 음악 없이 효과음 + 옅은 실내 잡음(pink 0.006) → 폰 촬영 느낌. 상품 트릭 영상은 음악 30초(길이 설정 30초, 110BPM 전후, 보컬 없음) + `promo.py beat`로 컷을 강박에 맞춤.
- 사용자가 만들기로 한 생성물은 기다린다(대신 합성하지 않는다).

## 5. 검수 (보내기 전 직접)
- 영상: 컨택트시트 + 프레임 차이(끝 튐, 이음새). **핵심 소품을 크롭해 시간순 타일**로 본다(손잡이 각도, 매듭, 다리 링크). 몸 동작이 맞아도 소품 상태가 안 바뀌면 불합격.
- 이미지: 손가락·다리 개수를 확대해 하나씩 센다. **팔·손은 어깨에서 손끝까지 따라가며 사람마다 2개인지 확인**(소품 든 손이 추가로 생기기 쉬움). 사용자에게 보낼 원본 프레임도 손이 흐릿·기괴하지 않은지 먼저 본다. 한글은 확대해서 글자별 확인. 번호판·로고는 흐림/크롭.
- 끝·중간 이미지: 시작 이미지와 차이 마스크로 배경 고정 확인.
- 판정은 통과/불합격 + 근거(초·수치)로 말한다.

## 6. 합본
- 세로 3:4(1080x1440) 또는 9:16, 30fps. 정지 구간은 배속 압축, 클립은 K-Last 기준으로 잇는다. 워터마크 `@pathtorich7` 흰색 50%, 오른쪽 위(주인공을 가리지 않는 구석).
- 도구: `scripts/promo.py`(slow / beat / peak / build), 단순 이어붙이기는 프로젝트 폴더 `build.py`(예: `work/week3/cat-door/build.py`).

- 대사 없는 상황극(애니·커플·동물)은 **자막 없이** 올린다. 생각하며 다시 보게 만드는 게 완주·재시청에 유리하다(자막이 있으면 한 번 보고 넘김).

## 7. 쓰레드 문구
- 구조: **첫 줄 = 감탄 훅 + 실제 검색어**(상품명에 들어가는 말, 예: "3D 모래 액자", "LED 나비 날개") → 장면 속 반전 1~2줄("~인 줄 알았는데 → ~") → **반응·판정 한 줄로 끝**. 4~6줄.
- 묻는 질문으로 끝내지 않는다(몇 번? 어떻게 생각함? = 숙제). 감탄형 "반칙 아님?"은 허용. 태클 걸 틈을 남긴 단정이 댓글을 부른다(예: "정답은 정답인데 애매하네 ㅋㅋ", "이건 그냥 생명체라고 봐야 됨").
- 페르소나는 1장 규칙을 따른다. AI 영상이면 쓰레드 AI 라벨.
- 본문에 링크·가격·구매 단어 없음. 영상이 보여 주는 걸 글로 다시 설명하지 않는다. 원작 문장 베끼지 않기. 결과는 프로젝트 폴더 `POST.md`.
- **GPT 초안 활용(승계할 장점)**: 사용자가 GPT 초안 여러 안을 주면 버리지 말고 장점을 골라 합친다.
  - 가져올 것: ①실제 검색어 상품명("3D 모래 액자", "LED 나비 날개") ②"~인 줄 알았는데 → ~" 반전 ③구체적인 감각 한 줄("걸을 때마다 불빛이 살짝살짝 흔들림", "물 흐르듯 천천히 내려옴") ④누구나 겪는 상황 공감("할 일 자꾸 미루게 생겼네", "안 쳐다볼 수가 있나") ⑤자연스러운 구어체 감탄("뭐야 ~;;", "~ 강림함ㅋㅋㅋ").
  - 버릴 것: 지어낸 사용 경험·주인 시점, 영상과 다른 장소·상황(영상은 광장인데 "아파트"), 영상 설명 반복, 7줄 이상.
  - 순서: 안별 장단점 표 → 가장 좋은 안 하나를 뼈대로, 다른 안의 좋은 표현 1~2개를 이식 → 구경꾼 시점으로 고친 최종안 1개 추천.
- 예시(통과): "밤산책 나왔는데 천사 강림함ㅋㅋㅋ / 강아지 등에 LED 나비 날개 달려 있는데 / 어두운 길에서 반짝반짝하니까 시선 강탈 / 하얀 털이랑 날개 조합 반칙 아님? / 이러고 걸어가는데 안 쳐다볼 수가 있나 😂"

## 8. 게시
- **쿠팡 글은 사용자가 "쿠팡 글"이라고 할 때만.** 그 외에는 쿠팡·링크·홍보를 언급하지도, 묻지도 않는다.
- 1단계 = 링크 없는 장면 글. 반응이 좋으면 2단계 = "어디서 파냐고 해서 찾아봄"류 홍보 글 + 첫 댓글에 쿠팡 링크(고지 문구는 사용자가 넣음, 경고 반복 금지).
- **링크는 홍보 전용 글에만.** 일반 글에 광고 댓글 금지. 일반 3~4 : 홍보 1. 터진 글 직후 24~48시간은 홍보 금지.
- 시간: 07:40 / 12:30 / 18:00~19:00, 주말 09:00도 후보. 2~3회 후 인사이트로 고정. 같은 영상을 그대로 두 번 올리지 않는다(2차는 "결과 먼저" 변형 + 다른 이미지·문구).

## 9. 진행 방식
- **분석 → 합의 → 진행.** 원본 분석은 컷·시간별로 상세히 한국어로 설명하고(무엇을 들고, 어떤 표정, 어떤 동작), 사용자가 맞다고 해야 다음 단계로 간다. 추측은 추측이라고 밝힌다.
- **생성 요청 전 사전 점검이 결과 검수보다 중요하다.** 요청마다 "원본 요소(인물·손·소품·표정·동작·시간·구도) ↔ 프롬프트 문장 ↔ 첨부 파일" 대조표를 만들어 빠진 것·모호한 것(왼/오른손, 거울 반전, @img 순서)을 먼저 고친 뒤 넘긴다.
- **비용이 걸린 설정(길이·해상도·형식·Hz·kbps)은 첫 요청에서 최소값으로 확정해 준다.** 요청을 드린 뒤에 "더 짧아도 된다"를 말하지 않는다. 음악 길이 = 영상 길이 + 약 3초(배경음은 쉼·강박을 고를 여유가 필요하면 그때만 길게, 이유와 비용을 같이).
- **수정 제안은 한국어로 "무엇을 → 어떻게 바꾸면 → 어떤 결과 예상 → 위험·비용"**을 적어 사용자가 판단하게 한다. 영어 프롬프트는 합의 후에 준다.
- 한 턴 = 한 아이템. 매 턴 "지금: X → 다음: Y".
- 아이템마다 한 번에 전부: **생성 파일명 / 첨부 파일명 / 모델·모드·길이·해상도·비율 / 완전한 프롬프트 코드블록 1개**. 빠뜨리면 사용자 크레딧이 낭비된다.
- 사용자 파일은 사용자가 쓰는 이름 그대로 부른다. 내가 만든 파일(K-Last, 소스 클립, 첫 프레임)만 프롬프트보다 먼저 SendUserFile로 보내고 캡션에 파일명.
- 긴 처리 전에 한 줄로 알린다. 작업물은 커밋·푸시.
- 추측으로 메뉴·가격·제한을 단정하지 않는다. 모르면 화면을 보내 달라고 한다.
