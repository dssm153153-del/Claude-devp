# coupang-product-promo

사용자가 쿠팡에서 파는 상품(예: 실크 스카프)을 바이럴 참고 영상과 같은 방식으로 홍보하려 할 때 쓴다. 대화는 한국어, 파일명은 영어. 공통 규칙(한 턴 한 아이템, "지금: X → 다음: Y", 프롬프트는 완전한 코드블록 1개, 파일명 규칙, 결과는 프레임·수치로 검수)은 `video-recreate-workflow` 스킬을 따른다. 이 스킬은 그 위에 **상품 홍보용으로 검증된 최적 경로**만 정리한다(eunchae-video, 2026-10).

## 시작할 때 받을 것 (한 번에 묻는다)
1. 참고 영상(바이럴 원본)과 그 쓰레드 원문(있으면 분석 결과도)
2. 상품 사진: 쿠팡 대표 이미지·스틸컷 2~4장(착용 모습 + 무늬가 잘 보이는 것)
3. 상품 사양: 크기·소재(예: 실크 90x90) — 원본 동작이 우리 상품으로 가능한지 판단
4. 인물: 나이대·국적, 얼굴 노출 여부(권장: 입술·턱 크롭)
5. 쓰레드 아이디(워터마크용)

## 최적 경로 (오늘 시행착오를 뺀 순서)
| 단계 | 할 일 | 도구 | 비용 |
|---|---|---|---|
| 1 | 원본 분석: 컷 위치, 구간별 동작, 상품이 안 보이는 구간 표시 | `video-recreate-workflow/scripts/analyze.py` + 0.1초 시트 | 0 |
| 2 | 구간 설계: 원본 컷 단위로 K1..Kn, **상품이 안 보이는 구간은 생성하지 않고** 전환+효과음으로 대체 | - | 0 |
| 3 | Ref-image 1장(인물+의상+상품, 원하는 크롭) | GPT | 이미지 |
| 4 | 첫 프레임 정답 이미지 C1-Start(3단계 방식, 아래) | GPT | 이미지 2~3장 |
| 5 | 구간별 **동영상 수정**(video-to-video) | Freepik 동영상 수정 → **MiniMax H3** | 990/클립 |
| 6 | 완성샷 C5 = 마지막 클립 끝 프레임에서 손만 지우기 | GPT 편집 | 이미지 |
| 7 | 합본(배속 복원, 9:16, 전환) | `scripts/promo.py build` | 0 |
| 8 | 음악 30초 + 효과음(휙/반짝) → 비트·정점 맞춤 | Freepik 오디오 | 소량 |
| 9 | 워터마크(@아이디, 상품 안 가리는 구석) | promo.py | 0 |
| 10 | 쓰레드 이미지(UGC 거울 셀카) + 문구 2~3안 | GPT | 이미지 |

### 방식 선택 핵심 (가장 중요)
- **손으로 상품을 조작하는 영상(매기·접기·감기·묶기)은 Kling Motion Control을 쓰지 않는다.** MC는 몸 동작만 복사하고 천이 감기거나 매듭이 생기는 변화는 복사하지 않는다(K1 실패: 손만 올라가고 스카프는 매달려 있음). 또 MC는 참조 영상에 머리+몸통이 다 있어야 해서, 얼굴 없는 클로즈업 원본은 감지 오류가 난다.
- **Freepik "동영상 수정"으로 원본 구간을 그대로 넣고 외형만 바꾼다.** 동작·천의 경로가 원본에 이미 있으므로 트릭이 살아난다.
- 모델: MiniMax H3(990크레딧, 이미지 여러 장) 사용. Runway Aleph 2는 2340크레딧에 이미지 1장. Kling 고급 버전 전환(300→1930) 안내가 떠도 바꾸지 말고 한산한 시간에 재시도.

### MiniMax H3 사용법 (반드시)
- 출력은 소스 길이와 무관하게 **약 5.17초·24fps 고정**, 비율은 9:16 또는 3:4로 나온다. 소스가 짧으면 남는 시간을 참조 이미지를 보고 **지어낸다**(K2 실패: 손 위 매듭 대신 목에 묶는 장면).
- 그래서 소스 구간을 `promo.py slow <src> <out> 5.2`로 **약 5.2초로 늘려서** 넣는다(minterpolate). 합본 때 `src_len`으로 원래 속도 복원.
- 소스는 컷 바로 다음 프레임부터 자른다(컷 직전 프레임이 섞이면 첫 장면이 튄다).
- 참조 이미지 순서: ① 직전 클립 마지막 프레임(K{n-1}-Last, 연속성) ② 첫 프레임 정답 이미지(C1-Start) ③ 상품 사진. 상품 사진이 "목에 두른" 착용 컷이면 프롬프트에 "그 착용 방식은 따라 하지 말 것, 이 장면에서 스카프는 손에 있다"를 쓴다.

### 3단계 이미지 방식 (C1-Start)
1) 원본 프레임(Pose-ref) 첨부 → "그대로 다시 그려라". **결과가 원본과 똑같이 나오는 게 정상**이라고 미리 말한다.
2) 1단계 결과 + Ref-image + 상품 사진 → "인물·의상·상품 무늬만 교체, 포즈·손·접힘 그대로".
3) 배경 교체는 몸통 클로즈업이면 생략.
- 2단계에 **원본 포즈에서 안 보이는 부위**(걷은 소매, 팔찌, 손목)를 지시하면 팔·손목을 하나 더 그린다. 보이는 부위만 쓰고 "손 아래엔 스카프와 니트만, 추가 손목·소매 금지"를 명시. 팔찌 같은 액세서리는 빼는 게 안전.
- 불합격 시 땜빵 편집 반복 금지 → 모든 요구사항을 담아 1단계 결과에서 새로 생성(-v2, -v3).
- 상품 무늬 검수는 상품 사진과 **확대해서 나란히** 비교(수채화풍·파스텔로 바뀌거나 테두리 색·폭이 달라지는 일이 잦다). 프롬프트에 "진한 빨강, 얇은 어두운 윤곽선, 파스텔·수채화 아님, 테두리 얇고 연한 라일락 그레이"처럼 색·선·폭을 수치처럼 적는다.

## 합본·오디오
- `scripts/promo.py build config.json out.mp4` (예시: `work/eunchae-video/scripts/promo.json`). 1080x1920 30fps, 3:4 클립은 가운데 1080 크롭, 생략 구간 자리에 smoothleft 0.2초 전환, 완성샷 1.2초 살짝 줌인.
- 음악: Freepik Music **길이 설정을 반드시 30초로**(기본값이면 5초짜리가 나온다). 템포 110BPM 전후, 보컬 없음. `promo.py beat music.mp3 0,3.6,5.43,8.4`로 컷이 강박에 맞는 시작 오프셋을 찾는다. 끝 0.7초 페이드아웃.
- 효과음: 최소 3초로 받는다. 한 파일에 여러 번 들어 있으므로 `promo.py peak`로 첫 정점을 찾아 그 구간만 자르고, 정점을 전환 순간에 맞춘다(휙 70%, 반짝 60%). 리미터 0.95.
- 워터마크: 흰색 50%, 40px, 오른쪽 위(스카프 끝이 지나가는 아래쪽 구석은 피함). 구간별 프레임으로 상품을 가리지 않는지 확인.

## 쓰레드 이미지 (C6-Threads)
- 화보형 대표 이미지는 광고로 보여 넘긴다. **휴대폰으로 얼굴을 가린 현관 거울 셀카**, 영상과 같은 착장·같은 매듭, 아침 햇살, 생활감, 약간의 노이즈. 첨부: 완성샷(C5) + 상품 사진.

## 쓰레드 문구 규칙
- **먼저 확인**: 계정 캐릭터(성별·나이·말투)와 판매 형태(직접 판매 / 쿠팡 파트너스). eunchae-video는 20대 남성 캐릭터 + 쿠팡 파트너스였는데 확인 없이 여성 1인칭 착용 후기로 써서 다시 썼다.
- 지어낸 1인칭 경험담(내가 샀다·내가 매봤다)은 쓰지 않는다. 캐릭터 시점의 발견·감탄·추천 + 매듭법 정보로 쓴다. 남성 캐릭터면 "남자인 내가 봐도", "여친·엄마한테 보내주기 좋음"(선물 각도).
- "광고 같지 않게"는 본문에 링크·가격·구매 권유를 빼고 정보·감탄 위주로 쓰는 것으로 해결한다. 고지를 숨기는 방식은 쓰지 않는다.
- 쿠팡 파트너스면 링크와 같은 첫 댓글에 약관 고지 문구를 그대로: "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." 직접 판매면 "#광고 제가 판매하는 제품".
- 구조: 첫 줄 비포·애프터 훅 → 방법 한 줄(상품 사양 포함, 예: "정사각 스카프 대각선으로 접어서") → 변화·만족 → 공감 고백형 마지막 줄("스카프 사놓고 안 쓰는 사람 나만 있던 거 아니지?").
- 글 속 옷·상품이 영상과 일치해야 한다(원문 "티셔츠" → 우리 영상은 "니트").
- 원작 계정 글의 문장을 그대로 쓰지 않는다(구조만 빌림).
- 안 2~3개(권장안 표시) → `copy/Threads-post.md` 저장.

## 이번 프로젝트에서 사용자에게 혼난 것 (반복 금지)
- 사용자가 올린 참고 이미지를 내 이름(Style-ref-A)으로 첨부 지시하면서 파일을 안 보냄 → 이름을 붙였으면 그 턴에 먼저 보낸다.
- 사용자가 올린 결과물에 -v1/-v2를 붙여 부름 → 사용자 PC 파일명 그대로 부른다.
- 결함 위치 설명만 하고 표시 이미지 없음 → 빨간 원 표시 이미지를 보낸다(편집 시).
- 스킬 사례를 조건 확인 없이 일반화(상반신 규칙) → 사례의 조건부터 확인.
- 작업이 오래 걸리면서 진행 상황을 말하지 않음 → 긴 처리 전에 한 줄로 알린다.
