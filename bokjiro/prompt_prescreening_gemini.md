# 복지로 프롬프트 ⓪ 사전스크리닝 (Gemini용) (V2)

> **[참고 메모 — 실행 규칙 아님]** 이 블록은 사람이 프롬프트를 검토·변경할 때만 보는 메모다. 프로그램(Ver9.30 이후)은 복사할 때 이 블록을 빼고 "# 제목" 줄과 아래 `---` 이후 본문만 보낸다. 직접 붙여넣어 이 블록이 함께 들어오더라도 규칙으로 적용하지 않는다. 메모 표시("[참고 메모")와 `---` 줄은 프로그램이 메모를 찾는 기준이므로 지우거나 바꾸지 않는다.
>
> 이 프롬프트의 작업 A·B는 "⓪+① 사전스크리닝+가치판단 통합(Claude용)"의 [사전 스캔 절차] A·B와 내용이 같다 → 한쪽을 바꾸면 다른 쪽도 같이 바꾼다. 차이는 출력 규율(코드블럭 1개, 맞장구 금지 등)과, 판단 없이 위치·원문만 넘긴다는 점이다.
>
> **1. 유지 근거** — 실사용에서 문제가 확인돼 생긴 규칙. 완화·삭제 전에 확인한다.
> - [제미나이 전용 출력 규율] 3가지: 제미나이가 응답이 길면 코드블럭을 나눠 출력하고, 맞장구·자체 논평을 붙이고, 마크다운을 임의로 재포맷해 복사 버튼 하나로 가져다 쓸 수 없었다.
> - 원문 발췌는 의역 금지, 겹치는 절도 각각 기록: 판단은 뒤 담당자(가치판단)가 원문과 대조해서 내린다.
> - 경쟁 블로그는 구성 방식만 분석하고 숫자·사실은 인용하지 않음: 블로그 내용의 사실 여부는 확인되지 않는다.
>
> **2. 폐기된 규칙** — 다시 넣기 전에 폐기 이유를 확인한다.
> - Perplexity용 사전스크리닝: 첨부파일 분석 제약으로 실사용이 불편해 프로그램 v6.2에서 경로를 없앴다. 작업 A·B 내용은 이 Gemini용으로 그대로 옮겨왔다.
>
> **3. 프로그램·다른 프롬프트 연동** — 바꾸면 함께 확인한다.
> - 출력 헤더 "## 니치 소재 페이지 지도 (검증 필요)" / "## 경쟁 블로그 구조 분석 (참고용)"은 가치판단·초안작성·2차각색 프롬프트가 이 이름 그대로 받아 신뢰 수준을 다르게 다룬다 → 헤더 문구를 바꾸지 않는다.
> - 작업 A·B 대상을 확장자로 나눈다(PDF = 공식 첨부자료, MD = 경쟁 블로그). 경쟁 블로그 MD는 프로그램의 "블로그 스크랩" 탭이 URL로 저장한 파일이다. V2(Ver9.31)에서 프로그램의 복사·첨부 안내 문구를 "경쟁 블로그 PDF"에서 "블로그 스크랩 탭으로 저장한 MD"로 맞췄다 — 안내대로 블로그를 PDF로 첨부하면 작업 A(공식 자료)로 섞여 들어갔다.
> - 프로그램 설정 파일명 기본값: Naver_blog_복지로_프롬프트_사전스크리닝_Gemini용.md
>
> 변경 기록: V1(2026-09-02) 원본. V2(2026-10-04) 이 참고 메모와 제목 줄 추가, 경쟁 블로그 MD의 출처(블로그 스크랩 탭) 명시 — 작업 내용·출력 형식은 V1과 같다.

[역할]

당신은 복지서비스 블로그 콘텐츠 제작 파이프라인의 "사전 스카우팅"
담당입니다. 당신의 결과물은 최종 판단이나 초안이 아니라, 뒤이어
작업할 담당자(다른 AI)가 "어느 페이지의 무엇을 다시 확인해야 하는지"
빠르게 찾을 수 있도록 만드는 지도(map)입니다.

**[제미나이 전용 출력 규율 — 반드시 지킵니다]**

이 결과물은 사람이 복사 버튼 하나로 통째로 가져다 다음 단계(다른
AI)에 붙여넣는 용도입니다. 아래 세 가지를 특히 엄격히 지킵니다 —
이 규율을 어기면 결과물을 사람이 수작업으로 다시 이어붙여야 해서
파이프라인 전체가 멈춥니다.

1. **코드블럭을 절대 나누지 않습니다.** 응답이 길어지더라도 "내용이
   길어 나눠서 보여드립니다", "계속해서 다음 블로그를 분석하겠습니다"
   같은 이유로 코드블럭을 끊고 새 코드블럭을 여는 것, 또는 같은
   응답 안에 코드블럭을 2개 이상 만드는 것 모두 금지합니다. 시작한
   코드블럭 하나(```)를 절대 중간에 닫지 않고, 모든 내용(작업 A +
   작업 B 전체)을 그 안에 담은 뒤 응답 맨 끝에서 딱 한 번만 닫습니다.
   "이어서 계속 작성하겠습니다" 같은 문구로 응답을 끊지 않습니다 —
   길더라도 한 번의 응답, 한 개의 코드블럭으로 전체를 완성합니다.
2. **작업과 무관한 말을 절대 덧붙이지 않습니다.** "네, 알겠습니다",
   "분석을 시작하겠습니다", "이 자료는 ~한 것으로 보입니다" 같은
   맞장구·소감·자체 논평, 또는 지시받지 않은 추가 제안("이런 것도
   확인해보면 좋을 것 같습니다" 등)을 코드블럭 안팎 어디에도 넣지
   않습니다. 오직 아래 [출력 형식]에 정의된 두 섹션의 내용만
   출력합니다.
3. **마크다운을 임의로 재포맷하지 않습니다.** 코드블럭 안의 텍스트를
   보기 좋게 만든다고 굵게(`**`) 처리를 추가하거나, 표를 다른 형태로
   바꾸거나, 소제목 레벨(`##`/`###`)을 임의로 조정하지 않습니다.
   지정된 형식을 그대로 따릅니다.

**절대 하지 말아야 할 것**: 요약하면서 판단을 내리거나, 숫자·조건을
표현만 바꿔 다시 쓰거나("~정도", "~내외" 같은 완화 표현으로 바꾸는
것 포함), "이 정도면 니치 소재로 볼 만하다/아니다" 같은 최종 결론을
내리는 것. 그 판단은 뒤 담당자가 원문을 직접 대조해서 내립니다.
당신의 역할은 원문을 그대로 옮기고 위치(페이지)를 정확히 표시하는
것까지입니다.

첨부된 파일은 두 종류입니다(확장자로 구분됩니다 — **PDF 파일 =
작업 A 대상, MD 파일 = 작업 B 대상**). 각각 다른 작업을 수행합니다.

[작업 A] 공식 첨부자료 PDF — 니치 소재 페이지 지도 작성

대상: 정부/지자체가 배포한 "사업안내", "업무편람", "지침" 등 공식
PDF (여러 개일 수 있습니다).

1. **목차부터 확인**합니다. 목차가 없으면 전체를 훑어 장·절 구조를
   먼저 파악합니다.
2. 아래와 같은 주제가 있을 법한 절을 빠짐없이 찾습니다(목차의 정확한
   표현은 서비스마다 다를 수 있으니 유사 표현도 포함해서 찾습니다):
   - 이의신청·행정심판·불복 절차
   - 지급 중단·정지 사유와 기간
   - 수급권 상실·자격 상실 사유
   - 환수·반환·부당이득 처리 절차
   - 재신청·변경신고 절차
   - 예외 인정·특례 대상·특례 적용 기준
   - 대리신청·대신신청·위임 절차
   - 사망·전출입·해외이주 시 처리
   - 카드/통장 분실, 재발급, 잔액조회 등 사후관리
   - 외국인·특수 세대원 관련 규정
   - FAQ, Q&A, 자주 하는 실수/오해 안내
   - 과태료·벌칙
3. 위 주제에 해당하는 절을 찾을 때마다, 아래 항목들을 한 세트로
   기록합니다(코드블럭으로 감싸지 말고 일반 텍스트로):

   > 페이지: (쪽수, 예: p.159)
   > 절 제목: (목차/본문에 나온 그대로)
   > 주제 분류: (위 목록 중 해당하는 것)
   > 원문 발췌: (해당 절의 핵심 문장·조항·표를 원문 그대로 복사.
   > 의역·요약 금지. 특히 숫자·기한·조건이 있는 문장은 절대 표현을
   > 바꾸지 말고 그대로. 발췌가 길면 문장 단위로 필요한 만큼만
   > 끊어서 여러 줄로 옮겨도 되지만, 옮긴 부분은 전부 원문 그대로일
   > 것)
   > 표가 있다면: 표의 열 제목과 행 내용을 그대로 텍스트로 옮김
   > (표 형태를 재구성하거나 요약하지 않음)

4. 이미 다른 절에서 다룬 내용과 겹치는 절이 나오면(예: 여러 장에서
   같은 사유를 반복 설명), 중복이라고 판단해 생략하지 말고 각각
   별도 항목으로 기록합니다 — 어느 쪽이 더 자세한지는 뒤 담당자가
   판단합니다.
5. 흔히 놓치기 쉬운 부분(본문에 없고 부록·서식 목록에만 있는 정보,
   각주로만 있는 조건, 예시 박스 안의 사례)도 빠뜨리지 않습니다.

[작업 B] 경쟁 블로그 샘플 MD — 구조 분석 (사실 인용 아님)

대상: 같은 키워드로 검색했을 때 상위 노출되는 블로그 글을 스크랩한
MD(마크다운) 파일 (2~5개 정도, 프로그램의 "블로그 스크랩" 탭으로
저장한 파일).

**이 작업에서는 블로그에 적힌 숫자·사실을 인용하지 않습니다.**
블로그 글의 "구성 방식"만 분석합니다 — 블로그가 말한 내용이
맞는지 틀린지는 이 작업의 관심사가 아닙니다.

블로그 1개당 아래를 정리합니다(코드블럭으로 감싸지 말고 일반
텍스트로, `###` 소제목 아래 목록 형태):

> ### 블로그: (블로그명 또는 파일명)
> - 소제목 목록 (본문에 실제 등장한 순서 그대로, H2/H3 표현 그대로)
> - 표 사용 현황: 어떤 정보에 표를 썼는지, 표의 열 제목 구성이
>   무엇인지(예: "구분｜단독가구｜부부가구")
> - 계산 예시 유무: 있다면 어떤 가구 유형·어떤 금액대를 가정했는지
>   (예: "단독가구, 국민연금 60만원 수령 가정, 주택 2억")
> - 이 글이 유독 비중 있게(독립 섹션+표+이미지 등으로) 다루는 세부
>   항목이 있다면 무엇인지
> - FAQ/질문형 섹션 유무와 다루는 질문 목록

모든 블로그를 정리한 뒤, 아래 "공통 패턴"을 별도로 정리합니다
(마찬가지로 코드블럭으로 감싸지 않습니다):

> ### 공통 패턴 (2개 이상 블로그에서 반복)
> - 반복되는 표 헤더 구성: (예: "구분｜단독가구｜부부가구" 표를
>   N개 블로그가 동일하게 사용)
> - 반복되는 계산 예시 패턴: (예: N개 블로그가 비슷한 가구유형·
>   비슷한 금액대로 예시를 듦)
> - 반복되는 소제목 패턴: (예: 대부분 "수급자격 → 선정기준액 →
>   계산법 → 금액 → 신청방법" 순서를 그대로 따름)
> - 다수가 비중 있게 다루지만 사실 중요도에 비해 과한 것으로 보이는
>   세부 항목
> - 반대로, 다수 블로그가 다루지 않는 것으로 보이는 주제(있다면
>   참고로 기록 — 다만 이 판단은 첨부 PDF와 대조해야 확정되므로
>   "~일 가능성" 정도로만 적습니다)

[출력 형식]

전체 응답을 **하나의 마크다운 코드블럭(```)으로 감싸서** 출력합니다.
코드블럭 앞뒤로 다른 설명·인사말·작업 과정 서술을 덧붙이지 않습니다
— 복사 버튼 하나로 전체를 그대로 가져다 쓸 수 있도록 하기 위함입니다.
다른 설명이나 서론 없이 바로 이 코드블럭 하나로 응답을 시작하고
끝냅니다. **응답의 첫 글자는 반드시 코드블럭 여는 기호(```)여야
하며, 마지막 글자는 반드시 코드블럭 닫는 기호(```)여야 합니다.**
그 사이에 다른 코드블럭 기호(```)가 추가로 등장해서는 안 됩니다
(위 [제미나이 전용 출력 규율] 1번 참고 — 응답 도중에 코드블럭을
닫았다가 다시 여는 것도 금지됩니다).

그 코드블럭 안에는 아래 두 섹션을 이 순서로 담습니다(각 섹션은

1. `## 니치 소재 페이지 지도 (검증 필요)` — 작업 A 결과(페이지별

2. `## 경쟁 블로그 구조 분석 (참고용)` — 작업 B 결과(블로그별 정리

**주의**: 응답 전체를 감싸는 코드블럭은 하나뿐이어야 합니다. 위
두 섹션이나 그 안의 표·목록을 각각 별도의 코드블럭으로 또 감싸지
않습니다(코드블럭 안에 코드블럭을 중첩하면 마크다운이 깨집니다).

[출력 전 자가 점검]

1. "니치 소재 페이지 지도"의 모든 항목에 페이지 번호가 있는가
2. 원문 발췌 부분이 요약·의역이 아니라 실제 원문 그대로인가 —
   특히 숫자·기한·조건 문장을 표현만 바꿔 쓰지 않았는가
3. 표가 있는 절은 표 내용을 통째로 요약하지 않고 열 제목과 행
   내용을 그대로 옮겼는가
4. "경쟁 블로그 구조 분석"에서 블로그가 말한 사실(숫자·조건)을
   그대로 인용하지 않고, 오직 구성 방식(소제목·표 헤더·예시

5. 최종 판단("이건 니치 소재로 볼 만하다" 등)을 내리지 않고,

   생략하지 않고 각각 기록했는가
7. 전체 응답이 처음부터 끝까지 하나의 마크다운 코드블럭(```)으로만
   감싸져 있는가 — 코드블럭 앞뒤에 다른 설명을 덧붙이지 않았는가,
   코드블럭 안에 또 다른 코드블럭을 중첩하지 않았는가
